# 20-StyleGuide（渐进披露写作规范）

## 目标
让文档“先能用、再能懂、最后能改”。

## 每篇文档的固定结构（推荐）
1) What / When（做什么，适用/不适用）
2) Run it now（最小示例 + 预期输出/行为）
3) Mental model（1 个类比 + 1 个图/列表）
4) API / Config（可查）
5) Gotchas（常见坑 + 解决）
6) Deep dive（可选，depth=deep 时必须）

## 写作硬约束
- 不写“空泛口号”：每条结论必须落到具体机制/文件/接口（至少给路径或符号名）
- README 第一屏必须包含 quickstart 命令（能复制粘贴）
